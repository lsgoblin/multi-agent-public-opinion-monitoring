# 风控盾需求规格说明书（V2）

> 更新日期：2026-10-02。状态：设计目标，未实现项不视为交付。依据：[新版命题](../sources/2026-09-30-新版命题-多智能体仿真舆情监测.md)；指标见[05](05-赛题指标映射表.md)，未决口径见[00](../planning/00-规划总览与待确认事项.md)。

## 1. 业务目标与边界

发现品牌、产品、理赔服务相关负面舆情，构建事件知识与角色社会网络，在动态社会仿真中判断升级/平息方向，形成图谱、情绪曲线、关键节点、风险等级和应对建议，支持及时预警与追问。既可独立 Web 使用，也可由投诉系统 AI 溯源模块调用。

投诉可作为事件输入；公开舆情、报道和回应也可构成真实事件包。历史事件可回测，但在线采集延迟须用实际在线观察验证。

## 2. 用户与核心场景

| 角色 | 场景与目标 |
| --- | --- |
| 消保/公关分析人员 | 配置品牌与事件范围、识别负面信息、查看传播及风险、审核应对建议 |
| 风险负责人 | 收取红色预警、查看原因与证据、追问情景及关键节点 |
| 数据/模型维护人员 | 核查来源许可、标注、模型配置、任务预算、失败和部署状态 |
| 评测人员 | 隔离留出事件、核对标签、复算识别与方向指标、审计时效和成本 |
| 投诉系统集成方 | 通过接口提交真实事件或样本、查看进度、获取报告与证据，不依赖 Web 点击 |

主要场景：在线采集发现事件并初警；人工输入真实事件触发补采与推演；历史 cutoff 新运行后对照真实后续方向；对报告进行自然语言追问并返回引用；在内网环境部署与复核。

## 3. 功能需求

| ID | 必需能力 | 可验收行为 |
| --- | --- | --- |
| V2-F01 | 多平台公开数据入口 | 逐平台查询范围、批次、获取方式、去重、实际覆盖与延迟，历史导入/在线采集分列 |
| V2-F02 | 语义识别与事件聚合 | 情感三分类、负面判断、品牌/产品/问题实体，事件与风险等级分开；不能只用关键词 |
| V2-F03 | GraphRAG | 实体关系抽取、来源锚定、图版本、图检索及其实际参与 Agent/报告生成的证据；不是仅绘图 |
| V2-F04 | 角色与长期记忆 | 网民、客户、媒体、KOL、监管等独立人设、局部观测、跨轮可检索持久记忆；不同角色不等于不同模型 |
| V2-F05 | 动态仿真 | 运行时决定动作、消息传播、情绪与记忆更新；≥500 Agent、≥30 轮；记录实际活跃决策与失败，不预设剧情 |
| V2-F06 | 方向判断 | 根据本次仿真给出升级/平息结论、窗口、证据和不确定状态，历史标签仅用于评测 |
| V2-F07 | 五模块结构化报告 | 传播路径图谱、情绪演化曲线、关键影响节点、风险等级、应对建议，全部读取真实轨迹和来源 |
| V2-F08 | 四级预警与通知 | 红橙黄蓝、初警/更新、去重/升级、企业微信与邮件适配、失败及送达状态，初警不等待长报告 |
| V2-F09 | Web 与追问 | 任务配置、进度、知识图谱、舆情看板、报告查阅、自然语言追问；回答绑定本次报告/运行证据 |
| V2-F10 | 服务化与独立运行 | 同一核心服务支持 Web 与集成调用，任务状态、报告和证据可获取；集成协议待明确 |
| V2-F11 | 成本控制 | 全任务的构图、记忆、Agent、报告、追问分别计量；任务 token 硬上限、费用预算及超限停止状态 |
| V2-F12 | 部署与审计 | Docker 一键部署、域内运行路线、外发边界检查、配置与版本记录；提供四类交付文档 |

## 4. 非功能与质量约束

- 时效：热点采集 ≤15 分钟，发现到红色推送 ≤30 分钟，事件输入到完整报告 ≤60 分钟；分别记钟，起止与统计量见 V2-Q02/Q07。
- 规模：正式验收至少 500 Agent 和 30 轮。小规模用于开发调试，不能用配置值或复制 ID 证明规模；中断任务不能计为完整成功。
- 可追溯：结论 → 交互记录 → 使用的图/记忆/来源版本；模拟路径与真实观察边分开，模型推断不写成既成事实。
- 可靠性：任务可取消、恢复、标 partial/failed；错误与旧结果明示。通知具备幂等与有限重试，不向真实业务人群自动发送测试消息。
- 数据边界：仅采集可使用的公开材料；脱敏、访问控制、必要日志与保留期明确。域内部署不仅是 UI 在本机，LLM/嵌入/图服务/日志也要满足边界。
- 安全处理：外部材料只作数据，不执行其中指令；图谱或检索内容不能修改系统规则或任务权限。可解释性用简短理由与证据，不要求展示模型隐含思维过程。

## 5. 数据需求

| 对象 | 必需内容与边界 |
| --- | --- |
| 来源记录 | 源 ID、平台/URL、内容使用范围、脱敏文本或摘要、发布时间精度、available_at 及依据、collected_at、批次；缺字段标未知 |
| 真实事件包 | 事件定义、主体、时间线、cutoff、输入/后续标签清单、来源与版本、历史可知性；多篇转载不是多个事件 |
| 情感标注集 | 正/中/负及负面标签、标注说明、标注人与争议处理、去重和事件归属；开发集与测试集独立 |
| 走势标签 | 预测窗口、升级/平息或待定标签、观察证据、覆盖和判断规则；不由待测模型自评为真值 |
| 知识图谱 | 实体、关系、事实主张、证据 ID、有效时间/可知时间、抽取版本；未经证实指控标为陈述 |
| Agent 记忆与轨迹 | persona、run/agent/round、局部观测、动作、状态变化、记忆来源及有效范围；历史标签不进入记忆 |
| 报告与通知 | 报告结论 ID、来源/交互引用、图与曲线数据；发现、触发、发送、受理/送达、重试、失败时间 |
| 成本与评测 | 实际模型、tokens、价格版本与估算/账单区分、预算；逐样本预测与标签、分母、失败/弃权、运行版本 |

评测集的确切事件数按 V2-Q06 确认；20 个候选仅为内部收集目标，未核实候选不能计入可评测事件。情感样本数量另定。

## 6. 验收方法

情感识别使用人工标注、混淆矩阵与未调参的测试集；负面“准确率”歧义未关闭前同时报 precision 和二分类 accuracy，三分类另报整体准确率。无负类真值时召回率不可验证。

走势方向按独立真实事件核对。可先提出“一致事件数/纳入测试事件数”的内部候选公式，处理平稳/未知/失败/弃权的规则须在评测前冻结，不默默剔除难例。同一事件转载、多个 cutoff 或多种子不能自动充当独立事件扩大分母。

所有图检索、角色记忆和报告输入须遵守 available_at ≤ cutoff。按事件/时间隔离开发、校准和测试；未来标签不得进入输入。知名历史事件的模型记忆风险需披露并做输入扰动核查。

提交 V2-K01—K12 的逐项结果及 5 类验收材料；口径或证据不足时标不可验证，未达指标时保留实测数值。Docker/内网、自然语言追问、企业微信/邮件和报告证据链都需功能测试；单次 API 成功不替代这些验收。
