# Day 3 动态多智能体工程决策

> 更新：2026-10-08。状态：Day 3 工程决策，非 G3 验收记录。用户随后另行授权 Day 4 本机工程及受限 Day 5 离线评测与交付准备；当前 Day 3 模型工程只保留百炼路径，真实来源外发仍未授权。依据：[新版命题](../sources/2026-09-30-新版命题-多智能体仿真舆情监测.md)、[架构设计](../design/02-系统架构设计.md)、[五日计划](03-五日施工计划.md)及[Day 2 受限复核](../records/23-Day2受限G2关口复核.md)。

## 决定

1. **轮次与参与。** 暂将一轮定义为一个同步时间步：冻结轮初状态，按 Agent 的局部观测并发请求独立决策，全部有效响应或显式失败落账后统一传播消息、更新状态和记忆。轮内并发数可配置，不能把批次顺序造成的信息泄漏当作交互。正式“并行”口径仍按 V2-Q04 待确认，不据暂定实现改写指标。目标运行必须记录 500 个不同 Agent 在 30 轮中的逐轮状态、参与和失败；只配置 500 个 ID 不算规模完成。
2. **独立性与来源。** 每个 Agent 拥有独立 persona、局部状态、邻居、消息收件箱和按 `run_id + agent_id` 隔离的持久记忆。新运行默认不继承旧运行记忆。图检索只读本次案例的截止快照及其版本，检索结果记录来源和 `available_at`；未知可见时间、`evaluation_only` 与截止后材料不能进入观测、消息种子或记忆。
3. **动态决策。** 每轮决策输入包含该 Agent 本轮可见的证据引用、邻居上轮实际动作所产生的消息、当前局部状态和检索出的自身记忆。动作在运行时由真实模型产生并校验；预定义动作枚举和状态更新规则可以使用，预写逐轮结果、回放、固定脚本或复制同一输出不能作为 G3 证据。消息传播必须改变后续轮次的可见输入，并在日志中连到触发动作与接收者。
4. **日志与失败。** 保存运行配置和版本、逐轮冻结状态摘要、每次请求与响应状态、Agent 动作、证据/记忆/消息引用、状态变化、传播边、重试、跳过与失败原因。区分配置人数、实际决策人数、逐轮活跃人数及完成轮数。模型调用失败不能悄悄改写为 `observe`；无有效动作时显式记失败和下一轮状态处理。
5. **费用闸门。** 当前单次完整任务费用上限为 ¥30.00，覆盖该任务的构图、Agent 决策、记忆处理及后续报告调用。发请求前按模型、价格版本、最大输入/输出 token 和并发请求数原子预留保守费用，回执后按实际 usage 核销；缺 usage 时保留保守预留并标未知。达到可用余额边界即停止派发，结果为 `partial`，不得记作完整 500 × 30。记录估算费用与供应商账单的区别，套餐或免费额度抵扣不把任务费用记为零。既往试验的单独授权额度不追溯提高。
6. **执行顺序。** 先验证独立状态与记忆恢复、消息因果、时间隔离、失败和预算闸门，再以 1×1、10×3、50×5、100×10、500×30 分级运行。测试替身只验证工程逻辑；G3 须另有真实模型的完整规模实测、实际用量和失败日志。上一级若暴露预算或稳定性问题，先修复或如实停止，不用小规模结果外推 G3 通过。

## 当前模型与外发边界

当前本机没有可用内网模型，也不足以运行本地模型。Day 3 只保留百炼北京地域 `qwen-turbo`/`qwen-flash` 的受限适配器和纯合成运行入口。可发送字段为虚构事件标题及摘要、匿名 Agent 角色与参数、局部情绪/信任状态、实际收到的模拟消息、该 Agent 自身记忆、轮次及允许引用 ID；不发送真实 SEC/Optum/黑猫材料、原始网页、账号、个人信息、其他 Agent 私有记忆或密钥。新收费试验仍需明确用途、调用次数和本次预算。历史 DeepSeek Day 3 代码已移出当前工程，已有运行结果只作为[历史验证](../records/25-Day3动态仿真工程验证.md)与[历史容量测量](../records/27-Day3纯合成调用预算上限实测.md)保留。

## G3 核验判据

G3 只在一次完整规模的实际运行可复核时再作关口判断：500 个独立 Agent、30 个完整时间步、逐轮真实决策与失败统计、跨轮消息和记忆引用的行为证据、可恢复持久记忆、图检索引用、总用量与费用均有运行记录。需分别报告配置数和实际参与数；任何预算触顶、未完成轮次、测试替身或回放都不记为通过。G3 证据不替代 Day 4 报告/预警，也不证明最终域内运行或正式赛题指标达标。
