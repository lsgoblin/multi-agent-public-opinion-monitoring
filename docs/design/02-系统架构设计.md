# 风控盾系统架构设计（V2）

> 更新日期：2026-10-04。状态：设计基线；Day 2 受限贯通已完成，动态仿真尚待实现。依据：[需求规格](01-需求规格说明书.md)。

## 1. 总体架构与复用

保留模块化单体 API + 独立任务 worker 的轻量部署方向，复用当前 Python/FastAPI、SQLite、案例导入和 cutoff 机制。业务前端只读取任务与证据；Streamlit 当前为 Day 1 工作台，能否承担图谱交互、规模进度与追问须原型验证，不预先宣布满足最终 Web 验收，也不立即重建前端。

主链：公开多源采集/真实事件输入 → 语义识别与事件聚合 → 截止快照 → 知识图谱与图检索 → 独立人设/记忆/社会网络 → 动态多 Agent 推演 → 方向判断与五模块报告 → 可追问证据视图。实时初警/通知在旁路独立触发，不等待 60 分钟报告；报告完成后更新风险依据。

投诉系统通过 API 使用同一引擎，独立 Web 直接连接 API；具体集成协议待确认。

## 3. 两类图与 GraphRAG

知识图谱表示公司、产品、事件、机构、事实主张及其关系，每条事实绑定来源和可知时间。投诉中的指控是带归属的陈述，不自动升格为事实。仿真社会网络表示 Agent、关注/接触/消息传播关系；实际观察边、推断边、合成边分开，不用合成网络证明真实传播路径被还原。

GraphRAG 最小有效链为：抽取 → 存储/版本 → 按问题或 Agent 观测检索实体及相关子图 → 返回证据与受 cutoff 限制的上下文 → 决策/报告引用。关键词候选筛选、向量召回或图邻域扩展的组合需试验，不把画图或全量材料直接塞提示词称为 GraphRAG。

初期可评估 SQLite 节点/边/证据表加内存图索引；仅当查询和并发实测需要时引入专用图/向量数据库。持久化与检索质量必须验证，技术选择不减掉图检索功能。嵌入模型的可用性、费用和域内运行单独核查。

## 4. 独立人设、记忆与动态循环

角色至少覆盖网民、客户、媒体、KOL、监管等命题举例；比例、参数和关系来源标为设计假设或已校准结果，监管动作明确为模拟，不声称还原具体人员。

每个 Agent 有 agent_id、persona、局部状态、邻居、独立记忆分区。长期记忆跨轮持久化，按相关性、时间和来源检索；压缩摘要保留原交互引用，不能混入未来标签。默认 run 隔离，避免上次测试结局污染新运行；跨运行复用须另行定义。

每轮：冻结起始状态 → 生成每个 Agent 的局部观测/图检索/记忆 → 受控并发 LLM 决策 → 校验动作和引用 → 同步传播与数值状态更新 → 写入轨迹和长期记忆 → 进入下一轮。预定义动作与更新规则可行，预定义各轮结果不可行。

批量决策仍需每个 Agent 独立上下文与输出，不能让无关角色互看私有记忆。输出中记录谁实际决策、失败、重试、跳过与原因；500 个静态标签不能代替 500 个有效 Agent。轮次/并行含义依 V2-Q04 冻结。

## 5. 规模、时效与成本

若暂以 500 Agent × 30 时间步、每步全员一次决策估算，是 15,000 个决策；这是容量假设，不是必须等量 HTTP 请求。任务总耗时还包括排队、采集、构图、检索、记忆与报告，不能用单次 2.56 秒探测直接承诺满足 60 分钟。

先按小规模 → 中规模 → 500 的分级试验测队列、轮耗时、token 分布、限流、数据库写入和内存。执行器设并发上限、供应商限流与有限重试，长任务支持取消/恢复。若采用轮内批次，需验证决策质量与上下文隔离；轮同步防止先完成者读取未定的未来状态。

预算覆盖构图、记忆摘要、Agent、报告及追问，并列出重试和失败成本。发送请求前预留 token 额度，完成后核销；并发原子预留，接近上限不再派发。费用依价格版本估算并与实际用量分开；未返回用量时标未知或保守估算，不能记零。超限输出 partial，不能伪装完整成功。

实时采集独立调度，逐渠道记录发布/首次可访问/发现/入库时间；历史重放不计实时。初警来自当前证据，后续仿真修订等级；企业微信/邮件记录受理与送达，不把本地日志写入当作实际推送成功。

## 6. 关键数据与接口（拟议，非现有实现清单）

| 契约 | 核心字段 |
| --- | --- |
| EventSnapshot | event_id、scope、cutoff、来源/标签隔离、可知性、数据版本 |
| KnowledgeGraph | graph_id/version、节点/边、事实主张、source_ids、valid/available_at、抽取与检索版本 |
| AgentMemory | run_id、agent_id、memory_id、内容摘要、源交互/证据、时间、可见范围、压缩版本 |
| SimulationRun | Agent 数、轮次定义/目标/完成数、实际决策统计、seed、参数、模型、预算与状态 |
| AgentAction | run/agent/round、局部观测/检索/记忆引用、动作、目标、理由、状态变化及失败 |
| ReportClaim | claim_id、所属五模块、结论、interaction_ids、source_ids、图/运行版本、不确定性 |
| Notification | alert_id、级别、发现/发送/受理/送达、目的地别名、重试、状态与去重键 |
| Evaluation | 指标定义、事件/情感测试集版本、标签、预测、分母、失败、耗时、成本 |

| 拟议接口 | 行为 |
| --- | --- |
| POST /events；GET /events/{id} | 真实事件/样本入口，提供截止快照与来源 |
| POST /graphs；GET /graphs/{id}；POST /graphs/{id}/query | 异步构图、读取版本、时间受限证据检索 |
| POST /simulations；GET /jobs/{id}；POST /jobs/{id}/cancel | 配置新推演、进度、取消，幂等和阶段错误 |
| GET /simulations/{id}/trajectory | 实际动作与状态，不生成展示用假轨迹 |
| POST /reports；GET /reports/{id}；POST /reports/{id}/questions | 五模块报告、引用、围绕冻结结果追问 |
| GET /alerts；GET /alerts/{id}/deliveries | 四级预警及通知证据，目的地凭据不暴露 |
| GET /runs/{id}/usage；GET /evaluations/{id} | 用量预算与逐指标评测明细 |

现有 /cases、/contracts 等骨架可复用；请求/响应最终契约由实现及接口文档确定，当前没有自动新增这些端点。

## 7. 参考路线与部署

[MiroFish 官方仓库](https://github.com/666ghj/MiroFish)展示 GraphRAG、动态记忆、仿真、报告和深度交互路线，并说明仿真依托 OASIS。当前默认示例包含云服务依赖，因此参考架构不等于原样复用或已经满足内网；复用前核查版本、许可、依赖和数据流。

开发验证模式可在获准范围内使用公网模型：Day 1 探测使用合成内容，Day 2 另完成一次[受限 SEC 摘要初测](../records/16-Day2DeepSeek受限情感初测.md)；该授权不自动扩展到 Day 3 或其他来源。严格域内模式要求 LLM、嵌入、图/记忆、数据库、日志与前端资源都在允许边界内；外部公开采集通过获准入口或导入边界进入，通知经批准出口。Docker 仅解决打包，不证明无外发。

计划 Docker 一键启动 API、worker、Web 和必要持久化；离线镜像/模型准备、健康检查、启动说明、无外发验证和最小访问控制纳入交付。当前不新增 Docker 配置或服务。前端技术与存储选型由原型和资源验证决定，不以换框架代替解决规模与证据问题。
