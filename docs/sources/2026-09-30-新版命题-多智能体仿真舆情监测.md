## 一、命题名称

多智能体仿真的保险舆情监测

## 二、命题描述

参考开源项目 MiroFish（群体智能预测引擎）的技术路线，构建面向保险行业的风险预警平台“风控盾”，主要需要实现的功能如下：

**舆情监测模块：**对接微博、抖音、小红书、黑猫投诉、新闻门户等公开渠道，实时识别与公司品牌、产品、理赔服务相关的负面舆情；基于 GraphRAG 构建事件知识图谱，生成具备独立人设与长期记忆的模拟智能体（网民、客户、媒体、KOL、监管等角色），在虚拟社交沙盘中推演舆情事件的传播路径、情绪演化趋势与关键放大节点，实现从“事后应对”到“事前预判”。

## 三、命题要达成的目标（可量化）

### （一）舆情监测部分

1. 数据覆盖：接入不少于 5 个主流公开平台，热点舆情数据采集延迟 ≤15 分钟。
2. 识别准确率：负面舆情识别准确率 ≥90%、召回率 ≥85%，情感三分类（正面/中性/负面）准确率 ≥88%。
3. 推演能力：单事件支持 ≥500 个智能体、≥30 轮并行仿真，推演结论（舆情升级/平息方向）与真实走势方向一致率 ≥70%（历史事件回测验证）。
4. 报告效率：从事件输入到产出结构化推演报告 ≤60 分钟，报告包含传播路径图谱、情绪演化曲线、关键影响节点、风险等级、应对建议五大模块。

### （二）通用要求

1. 预警时效：红色（重大）预警从发现到推送 ≤30 分钟，支持红/橙/黄/蓝四级预警及企业微信/邮件推送。
2. 成本可控：单次推演的 LLM Token 消耗可统计、可配置上限，标准推演任务平均成本不高于设定预算。

## 四、验收标准

1. 功能验收：端到端演示——输入一个真实舆情事件或历史投诉样本，系统在规定时间内自动完成采集、图谱构建、多智能体推演，输出含五大模块的分析报告与预警等级。
2. 指标验收：在不少于 10—20 个历史真实舆情事件上，验证上述量化指标达标，并提交测试报告。
3. 可用性验收：提供 Web 界面（参考 MiroFish 前端），支持任务配置、进度监控、知识图谱可视化、舆情看板、报告查阅与自然语言追问；支持 Docker 一键部署，可内网化运行、数据不出域。
4. 合规验收：仅采集公开数据，遵守平台协议与《个人信息保护法》要求；报告结论可溯源（每个结论能追溯到具体智能体交互记录和原始数据来源）。
5. 文档验收：交付部署文档、接口文档、使用手册与测试报告。
