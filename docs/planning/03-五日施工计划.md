# 五日施工计划

> 更新：2026-10-02。五自然日是可演示版本目标；用户已授权启动 Day 2，尚未授权 Day 3—5。G1—G5 是内部关口，不等于主办方正式验收。

关键路径：可证实的真实事件与 cutoff → 采集/识别/GraphRAG → 独立人设和记忆 → 动态推演 → 报告、预警与独立回测。

| 日 | 工作与交付 | 关口 |
| --- | --- | --- |
| Day 1 | 真实事件包和时间证据；五平台路线；情感/走势规则；模型探测、完整任务费用估算与域内技术路线 | G1：至少一条真实事件输入在 cutoff 前公开可见且有证据，未来材料隔离；其余准备项可评审 |
| Day 2 | 多源采集适配、去重与延迟观测；情感三分类、事件聚合、证据化构图和图检索 | G2：真实事件从采集到图检索贯通，初测有人工标签和真实检索引用 |
| Day 3 | 独立人设、局部观测、持久记忆和动态交互；从小规模扩至 500 Agent × 30 轮 | G3：跨轮行为受新消息和记忆影响，日志记录活跃决策、失败、用量及完整规模实测 |
| Day 4 | 五模块报告、四级初警、企微/邮件适配、Web 操作和 Docker 域内部署 | G4：真实任务可操作演示，报告可追溯；计时、通知和无外发各有运行证据 |
| Day 5 | 冻结版本；独立真实事件回测；指标、成本、部署和四类交付文档 | G5：逐项提交可复算结果；未达或不可验证的指标明示 |

Day 1 已有五平台状态、一次 DeepSeek 合成探测、预算情景、¥2.38 单任务上限及域内方案；黑猫原投诉的历史可见证据仍缺，现以有同期独立抓取证据的 UnitedHealth Group 事件完成 G1 输入与隔离复核，见[06](../records/06-Day1执行与验收记录.md)。Day 1 不要求五平台实时接通、真实样本模型质量、GraphRAG 实现或 500×30 实测。

Day 2 的书面 G2 条件已[内部受限通过](../records/23-Day2受限G2关口复核.md)。在线覆盖、延迟、真实跨事件聚合和正式情感评测继续追踪；Day 3 仍待用户明确授权。

风险处理：缺原投诉历史证据就换可在结果发生前捕获的事件；来源受限逐项报告，不以历史导入冒充在线覆盖；预算或设备不足时先缩上下文、测活跃比例，再如实列明未达规模；云模型演示不能代替数据不出域验证。所有阶段都保留来源、时间与未来标签隔离。
