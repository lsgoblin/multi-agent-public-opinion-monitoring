## 当前工程链路

当前是 Python/FastAPI 与 Streamlit 组成的本机应用，SQLite 保存案例、截止快照、证据图、仿真、任务、报告和预警。后台任务在 API 进程内线程执行，重启中断的任务不会自动续跑。Compose 提供 API、Web 和本机入口容器；已验证本机功能与完成任务的重启持久化，未验证所有容器无外发或目标内网部署。[部署文档](../delivery/deployment.md)和[API 参考](../delivery/api.md)给出当前运行方式与接口。

## 四分支共享契约

- **时间与来源：**案例身份、`cutoff`、来源版本、历史可见时间和 `evaluation_only` 标记从导入贯穿图、仿真与评测。后续走势只能在评分侧读取，不能进入截止图、检索、记忆或推演。
- **运行与结果：**区分配置 Agent 数、实际决策人数、请求机会、有效/失败决策和完成轮数。运行、任务、报告与预警须保留可核对的案例/图/运行 ID；`complete` 的单一字段不能替代有效性检查。
- **证据与展示：**报告结论应能回到合格原始来源和具体 Agent 动作、消息或记忆；无法支撑的结论说明不确定。Web 与交付报告需明确 `offline_dynamic_substitute`、暂定规则和通知 `dry_run`。
- **接口变更：**[API](../../src/riskshield/api.py)、[schema](../../src/riskshield/schemas.py)、[存储](../../src/riskshield/store.py)、[任务](../../src/riskshield/tasks.py)及模型网关为共享契约。分支先提交字段、状态、迁移及兼容性影响，总 Agent 统一集成；不得靠单分支局部测试宣称主干通过。

## 下一步设计决策的证据门槛

1. **评测优先形成非零合格分母。** 冻结独立历史事件及后续观察窗；先验证来源许可、可见时间、人工标签和预测配对，再扩充至命题要求的 10—20 件。正式分数须附逐单位排除原因和分子/分母。
2. **规模优化先定位瓶颈。** 离线分级运行可验证调度与资源，但真实模型完整 500×30、交互作用及成本须另外留证。更改并发、重试、记忆或模型路由后冻结配置和输出，不能沿用旧运行时长。
3. **追问从证据契约出发。** 新增自然语言和上下文能力时，所有回答仍以当前案例 cutoff 合格来源为界，保存引用和无证据回应；是否更换图检索实现由验证结果决定。
4. **通知和域内边界单独验收。** 四级规则测试、离线载荷、沙箱发送/回执、真实红警 30 分钟时效及容器出口审计是不同证据层级。新增外部调用、真实发送或部署仍按项目授权执行。

当前源码是可运行的本机原型，不应把上述目标设计写成既有能力。新的跨分支决策应形成新的“名称-YYYY-MM-DD.md”设计版本或更新相应接口文档，并在[测试与运行报告](../delivery/test-report.md)记录实际验证；旧稿只供溯源。
