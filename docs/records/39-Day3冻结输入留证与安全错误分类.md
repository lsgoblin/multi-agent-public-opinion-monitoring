# Day 3 冻结输入留证与安全错误分类离线实现

> 2026-10-06。针对[100×10 分级试验](36-Day3百炼混合100x10分级试验.md)暴露的 26 次 `qwen-flash` schema 失败和[37 号审计](37-Day3消息对照候选离线审计.md)发现的历史请求留证缺口，本轮只改工程与离线测试；**没有发起网络或模型请求，也没有追填历史结果**。

## 已实现

- `simulation_actions` 增加兼容旧 SQLite 的 `request_audit`、`schema_diagnostics` 可空字段。每次百炼决策在原有 `httpx.post(json=...)` 发送方式前，由适配器记录准备发送的 payload 规范 JSON SHA-256、系统提示 SHA-256、适配器契约版本，以及冻结局部状态、虚构证据、收到的消息、自身记忆和允许引用 ID 的规范 JSON 哈希。成功与已准备 payload 后的失败均留证；在派发前失败仅标记 `before_dispatch`，不伪造请求哈希。
- Pydantic 决策 schema 失败仅记录 `agent_id`、`action`、`evidence_ids`、`reason` 或 `other` 的字段类别，以及固定错误类型／`other` 和计数；异常消息、响应正文、`msg`、`input`、`ctx`、`url` 不入库。其他失败沿用不含正文的安全类别。
- 脱敏运行 JSON 的逐项 trajectory 同步包含这两个已校验字段；旧记录对应值为 `null`。[候选对照审计](37-Day3消息对照候选离线审计.md)遇到新留证时会重算并核对，哈希不一致则拒绝输出候选。

## 验证与边界

离线测试覆盖有效请求、供应商失败与 schema 失败、派发前失败、未知字段／错误类型白名单、旧表迁移、JSON 脱敏报告和对照哈希拒绝。相关 runner 测试 **12 passed**；最终全量 **105 passed**；`git diff --check` 无差异错误。历史 SQLite/JSON、`.env` 和模型提示未改，未提交、推送或部署。

留证哈希基于**准备发送的 payload 对象按键排序后的规范 JSON**，不是 HTTP 实际发出的字节哈希；适配器发送方式未变。历史 100×10 的 26 次失败没有这些字段，不能倒推具体 schema 错误。本次只提高后续调用的可诊断性，不证明稳定性或消息因果，**G3 仍未通过**。拟议的小额真实对照范围与判读条件见[38 号方案](38-Day3消息因果小额真实对照方案.md)；该方案尚未获新的收费授权，也未执行。
