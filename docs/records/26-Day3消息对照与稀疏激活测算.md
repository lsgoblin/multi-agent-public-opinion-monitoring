# Day 3 消息对照与稀疏激活测算

> 2026-10-05。全部为离线工程、测试替身和算术测算；没有新增 DeepSeek 调用，不构成 G3 证据，不改变 500 Agent × 30 轮指标。

## 消息与提示词检查

首次真实模型运行使用的 `day3-synthetic-agent-decision-v1` 提示词允许模型查看消息，但当时引擎消息只持久化 `message_id`、发送者、动作和证据 ID，发送动作的理由没有作为消息正文传播；云端字段又只保留消息 ID、发送者和动作。该设计能证明隔离和引用，却不足以给接收者提供清晰的新社会信号。

离线修改后的 `day3-synthetic-agent-decision-v2-message-content` 做了三项调整：

1. `share`、`comment` 和 `express_complaint_intent` 动作把发送者的 `reason` 持久化为消息 `content`，同时保留消息 ID、发送者、动作和其直接证据 ID。
2. 下一轮冻结观测向接收者提供上述完整消息字段；写入接收者记忆时也保留消息 ID、动作和正文。旧 SQLite 表启动时自动增加空默认值的 `content` 列。
3. 拟供后续真实模型验证的提示词明确说明：消息来自另一 Agent 上一轮的运行时动作，是新的社会信号而非已核实事实；只有在消息实质影响决策时才引用 message ID 并在理由中说明影响。

以上字段设计已通过 mock 后端检查，但 v2 提示词**尚未调用云端**。

## 同种子消息对照

[自动化测试](../../tests/test_day3_simulation.py)运行两个完全离线的 2 Agent × 2 轮纯合成 run，使用相同 seed `31415`。接收者 `agent_0001` 第一轮的人设、状态和证据完全相同；唯一计划差异是处理组的 `agent_0000` 执行 `share`，对照组执行 `observe`。

| 链路位置 | 处理组 | 对照组 |
| --- | --- | --- |
| 第一轮发送者动作 | `share` | `observe` |
| 发送理由 | `Runtime sender reports the fictional service interruption.` | `No social message is sent in the control run.` |
| 生成消息 | `msg_1_agent_0000_agent_0001` | 无 |
| 第二轮接收者观测 | 看见消息 ID、`share`、虚构证据 ID 和正文 | 收件箱为空 |
| 第二轮接收者动作 | `comment` | `seek_clarification` |
| 处理组引用 | `msg_1_agent_0000_agent_0001` | 自身 memory ID |
| 处理组理由 | `Received msg_1_agent_0000_agent_0001; comment to ask whether the fictional report is confirmed.` | 自身历史只导致求证，不评论 |

完整脱敏链路见[离线对照 JSON](../../data/research/day3_offline_message_control_20261005.json)。这证明运行时动作 → 持久消息 → 下一轮局部观测 → 引用消息的不同动作在工程上连通；决策来自确定性测试替身，因此不能证明真实模型会受消息影响。

## 稀疏激活费用测算

首次真实运行的平均单次用量为输入 `8,817 / 30 = 293.9` tokens、输出 `1,647 / 30 = 54.9` tokens；平均估算费用为 `¥0.036972 / 30 = ¥0.0012324`。以下只按该样本均价线性外推，不是报价、账单或质量保证。所有方案仍让 **500 个 Agent 每轮执行本地状态更新**，只改变当轮调用模型做新决策的人数。

| 方案 | 每轮模型决策人数 | 每轮本地状态更新人数 | 30 轮模型决策总数 | 费用估算 | 对 500×30 全员逐轮决策指标 |
| --- | ---: | ---: | ---: | ---: | --- |
| 全员逐轮云端 | 500 | 500 | 15,000 | ¥18.486 | 满足人数/轮次数量口径，但超预算 |
| 5% 轮换激活 | 25 | 500 | 750 | ¥0.9243 | 不满足 |
| 10% 轮换激活 | 50 | 500 | 1,500 | ¥1.8486 | 不满足；每个 Agent 平均仅 3 轮模型决策 |
| 消息优先且预留约10%预算 | 首轮 50；后续20轮×58、9轮×57 | 500 | 最多 1,723 | ¥2.1234252 | 不满足；约留 ¥0.2365748 给其他模型阶段 |
| ¥2.36 全额理论上限 | 24 轮×64、6 轮×63 | 500 | 1,914 | ¥2.3588136 | 不满足；没有给构图、摘要或报告留预算 |

“最多测试次数”需要区分口径：按本次实际平均费用，¥2.36 最多支持 **1,914 次单 Agent 模型决策**；第 1,915 次累计估算为 ¥2.360046，超过上限。若每个小规模测试固定为 10 Agent × 3 轮、30 次调用，则最多支持 **63 个完整测试批次**，共 1,890 次调用、估算 ¥2.329236；第 64 批累计约 ¥2.366208。若按每次 1,200 输入和 160 输出 tokens 的最坏预留 ¥0.004416 计算，只能预留 **534 次调用**，即 **17 个完整30调用批次**。这些数值都未给构图、记忆摘要或报告留预算。

稀疏方案可按“新证据接收者、收到高影响消息者、状态变化超过阈值者、轮换补位者”的顺序选取模型决策 Agent，其余 Agent 只使用确定性的本地传播和状态更新。运行记录必须逐轮分别输出 `model_decision_agents` 和 `local_state_update_agents=500`，并保留未调用模型者的选择原因。该方案只能作为降本实验，不能把 1,500、1,723 或 1,914 次模型决策改写为 15,000 次，也不能据此通过 G3。

## 当前结论

- v2 消息字段和提示词已离线实现并测试；没有追加云端调用。
- 同种子对照已定位并验证消息链路，但只属于测试替身排查证据。
- 按本次真实均价，500 × 30 全员逐轮 DeepSeek 调用约 ¥18.486，与测算时的 ¥2.36 上限不相容，也超过后续提高的 ¥5.00 上限。
