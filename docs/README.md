## 4. 优先级与冲突处理

P0/P1/P2 用于任务和未决事项，不给整篇文档评级。当前 Day 1 优先级见 10 任务书；统一未决事项编号见 00，避免另起一套相同清单。文档状态与任务优先级不同，“当前有效”也不代表功能已经完成。

冲突处理按事项判断：

1. 工作授权以用户最新明确指令为准；文档或任务书不能自行扩大实施范围。
2. 赛题数值与评分以原始要求及明确的后续澄清为依据。用户转述的资源变化可以更新实施前提，但不自动改写指标公式或验收目标。
3. 同一工程决定以最新、明确记录且有依据的变更为准。09 已更新会议 C07 的资源前提，原会议仍保留，不将其旧承诺视为已交付。
4. 已实现能力以当前代码、真实产物和对应日期的验证记录为准。设计方案、配置存在、模拟响应均不能替代实测。
5. 无法确定时写入 00 的待确认项，继续不依赖该结论的工作，不凭编号较大推断更有权威。

## 5. 维护约定

- 保留现有编号。新文档按用途归类，使用清楚的名称；不为保持全局连续编号而反复改名。
- 一项事实指定一个主要维护位置，其他文档放简短引用；确需同步需求或接口时只改受影响部分。
- 执行报告按日期追加真实结果，不用新结论覆盖原测试历史。已被取代的方案说明替代来源，必要时再归档，无需预建空归档目录。
- 新建独立文档时，标明日期、状态、范围和相关依据，并更新本索引。任务 A/B/C 尚未生成的报告暂不建空文件或有效链接，路径见任务书。
- 移动文件后检查 Markdown 链接和任务书中的纯文本路径；业务代码、数据目录和运行命令不随文档迁移而移动。
