# Day 3 消息对照候选离线审计

> 2026-10-06。针对[100×10 分级试验](36-Day3百炼混合100x10分级试验.md)的本地 SQLite，只读构造一组后续可核验的消息处理／对照候选。本次没有网络请求或模型调用，**不是消息因果试验，也不是 G3 验收**。

## 方法与结果

- 新增只读入口 `riskshield.day3_bailian_causal`。它用持久化 seed、角色、逐轮决策、消息和记忆在当前引擎代码下重建冻结观测；任一账本不一致则拒绝输出候选。测试拦截 HTTP client 创建，并验证 SQLite 文件哈希不变。
- 在真实 100×10 数据库中，100/100 人设、邻居和最终状态，1000/1000 观测引用，1395/1395 消息边及内容，2149/2149 记忆及内容均与当前代码重建一致。选中第 4 轮 `qwen-flash` 接收者 `agent_0019` 对第 3 轮实际消息 `msg_3_agent_0018_agent_0019` 的引用。
- 处理与对照的重建请求仅在 `received_simulated_messages` 中该条消息、`allowed_citation_ids` 中该消息 ID 上不同；自身状态、记忆、其他证据、系统提示、模型及生成设置相同。审计只输出标识、检查数和两份**当前代码重建 payload 的规范 JSON SHA-256**，不输出消息正文、完整提示或密钥。
- 新增 5 项离线测试通过；相关回归 49 passed、1 warning；全量回归 100 passed、1 warning。`git diff --check` 通过。

## 证据边界与下一步

历史运行未逐请求保存原始脱敏 payload 哈希、提示／适配器版本或冻结局部状态快照。因此这两份重建哈希不能证明与当时 HTTP 请求逐字节一致；构造对照也没有产生任何对照模型决策，更不能证明消息导致动作改变。未来运行应逐请求保存脱敏 payload 哈希、提示与适配器版本、冻结状态以及消息／记忆／图快照的引用证据。

100×10 的 26 次 `qwen-flash` schema 失败也无法从既有脱敏记录追溯具体字段。后续可在不保留响应正文的前提下，仅记录 Pydantic 校验错误的白名单字段名、固定错误类型及计数；不得记录 `msg`、`input`、`ctx`、`url` 或原始响应。完成离线诊断与证据接口后，再另行提出小额真实对照方案。三档分级授权已用完，500×30 未获授权；**G3 保持未通过，不进入 Day 4**。历史 cutoff 继续采用“首次有证据证明输入可见的时间 + 30 分钟”。
