## 3. 工作包 A：初始公开数据与质量审计

**可转发指令：你负责工作包 A，目标是取得可追溯的 Day 1 样本并判断连续日序列是否可得，不建设完整采集平台。**

### 任务

1. 核查黑猫投诉的目标主体列表、历史分页和详情；可选其他公开来源，但分别记录。先以 2024 年营销骚扰为候选，如可得性差，再比较其他案例，不为凑数混入无关主体。
2. 先核查约 30—50 条详情的字段与覆盖，可行后以约 70 条投诉 + 30 条舆情/响应材料为首批目标；前一步样本计入总数，不重复计算。数量为内部目标，不足时交付实际数量、限制及备选方案，不补造。
3. 投诉至少记录平台、源 ID、来源链接、发起时间、公开时间证据、本次采集时间、主体核实结论、主题、脱敏摘要、批次和重复关系。当前状态及后续回复与首次内容分离。
4. 以平台 + 源 ID 去重；主体不明记录隔离。不能仅凭“众安”关键词纳入，也不能仅凭“贷款”关键词排除，需核查法律主体与业务范围。
5. 指定五渠道逐项登记实际获取数量、查询范围和受限原因；news 类新闻不算微信原帖。单例不要求强行凑齐五渠道原帖。
6. 产出覆盖审计：候选时间窗口、列表能否连续枚举、页码/游标范围、失败、缺失、最早和最晚时间、重复与排除数量。只查搜索引擎时明确“搜索样本”，不得标为完整枚举。
7. 生成有限范围的按日观察统计和记录映射。部分采集标 partial，未覆盖为缺失，只有范围完整且无记录才记真实零值。抽样统计不得命名为公司或平台全量投诉。
8. 核查后续扩展约 90—180 日的可行性即可；Day 1 不要求完成全部历史采集。是否足够训练由 C 判断，不能以条数或天数直接保证预测准确率。

### 文件边界及交付

- 新增脱敏数据：`data/public/day1_initial/`，建议包含 `complaints.jsonl`、`public_opinion.jsonl`、`daily_observations.json`。
- 新增来源与覆盖记录：`data/research/day1_initial/`；有未脱敏临时材料时，仅放被忽略的 `data/private/`，不将其作为可提交产物。

**验收：**实际保留的样本均可追溯，统计能对应源 ID，重复不增加计数，无个人敏感字段，覆盖不足显式标记。无法采到时交付可复核的失败记录与替代路径，状态为受阻，不宣称数据任务成功。达到 100 条不是独立的通过标准。

## 4. 工作包 B：DeepSeek 接入与真实探测

**可转发指令：你负责工作包 B，目标是完成 Day 1 的真实结构化模型接入；不开发 NLP 流水线或多智能体引擎。**

### 任务

1. 阅读现有 `model_gateway.py`、`cli.py` 和相关测试；保留兼容 Chat Completions 的现有入口，不更换后端架构。
2. 查阅 DeepSeek 当时有效的官方接口和模型说明，记录核查日期及链接。此前研究建议先评估 deepseek-flash；实际名称与可用性要重新确认，不将旧教程或本任务书当作服务可用证据。
3. 检查思考模式、JSON 输出、最大输出 tokens、超时和 finish_reason。当前探测为 512 tokens、30 秒，未显式选择思考模式；需根据实际接口增加明确、可配置的选择，避免无关提供方被强塞专有参数。

## 7. 统一回报格式

每个子 Agent 使用以下结构交付：

1. **完成情况**：完成 / 部分完成 / 受阻，分别说明实现与资源状态。
2. **修改文件**：逐项列出路径及用途；说明未触碰的既有变更。
3. **实际证据**：数据数量与覆盖 / 真实模型结果 / 校验命令及结果，附报告位置。
4. **未完成项**：原因、具体需要的资源或确认，不写笼统“需要更多数据”。
5. **集成事项**：需要主 Agent 调整的共享契约、接口或文档。
6. **停止状态**：是否有临时进程、未结束采集或其他需处理事项；完成后不自动推进后续天数。
