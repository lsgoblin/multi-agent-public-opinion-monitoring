# 标题级情感人工标注操作说明

> 分支 `data-evaluation`，2026-10-11。本文是**操作说明**，不是冻结证据，也不取代
> `blind-sentiment-reannotation-packet-v19.json` 里的字段。用于安排 v19 的 14 个标题、
> 27 个独立标注槽位。

## 1. 谁在什么时候做什么

| 角色 | 做什么 | 不做什么 |
| --- | --- | --- |
| 工作 Agent（data-evaluation） | 出答题表、提交壳、标注规则页；人填完后做校验、冻结、计分 | **不填写任何 label / rationale / confidence** |
| 标注者 A、B（真人） | 各自独立判断标题文字的情感并填写答案单 | 不看预测、不看 AI 建议、不看对方答案、不看旧摘要答案 |
| 总 Agent | 确认允许标签集合；确认争议与弃权规则 | — |

**为什么 Agent 不能代填：** 计分器只接受 `independent is True` 且 `prediction_seen is False`
的标注。Agent 生成的标签属于 AI 标注，冻结协议明确禁止它充当人工真值。
一旦代填，该指标就失去意义。

## 2. 判断对象

**只看冻结标题文字本身**（`text_to_annotate` 字段），不判断：

- 底层事件是否真实、是否严重；
- 公司整体声誉或公众整体情绪；
- 后续走势、处理结果、是否平息。

原文标点与末尾换行按冻结文本保留，不改写、不补全。

**判定问题原文：** 仅判断冻结标题本身表达的情感倾向，不判断底层事件真假，
也不代表公众整体情绪。

## 3. 判定标准（冻结文本原文）

| 标签 | 定义 | 是否可用 |
| --- | --- | --- |
| `negative` | 标题明确表达不满、担忧、指责、损失或其他负向评价。 | ✅ |
| `neutral` | 标题主要陈述事件或引用诉讼指称，没有清晰的评价立场。 | ✅ |
| `positive` | 标题明确表达赞许、支持、满意或其他正向评价。 | ✅ |
| `uncertain` | **当前无定义**（见第 8 节待确认项）。 | ⚠️ 待确认 |
| `mixed` | 标题同时表达清楚的正向和负向评价，且不能归为单一方向。 | ❌ 已定义但不在允许集 |
| `unclear` | 标题过短、歧义过大或无足够表达线索，无法判断语气。 | ❌ 已定义但不在允许集 |

**注意这个冲突**：`mixed` 与 `unclear` 有定义但不允许使用；`uncertain` 允许使用但无定义。
在总 Agent 确认前，建议按第 8 节选项 1 处理：可用 `uncertain` 表达"无法判断"，
并在 rationale 里写清原因。

## 4. 填写步骤

1. 打开答题表 `review-sheet-v1.csv`（由工作 Agent 生成，见第 6 节）。
2. 逐行只读两列：`unit_id`、`text_to_annotate`（以及来源版本/时间列作为上下文）。
   **其余列在判断完成前不要看**，特别是任何 prediction 或旧答案列。
3. 按第 5 节的顺序判定 `label`。
4. 写 `rationale`：一句话说明标题的哪个词或结构支撑该判断。
5. 写 `confidence`：0.0—1.0，表示你对**这个标题文字判断**的确定程度，
   不表示对事件的把握。
6. 填 `annotator_id`（你自己）、`submitted_at`（带时区，如 `2026-10-12T10:00:00+08:00`）。
7. 填 `prediction_exposure` 与 `saw_other_annotator_answer`，必须如实。
   若你曾看到任何预测或另一位标注者的答案 → 填 `true`，该条会被排除（这是保护，不是惩罚）。
8. 交给工作 Agent 校验。

## 5. 判定顺序（按此顺序问自己）

1. 标题是否**明确表达**不满、担忧、指责、损失或其他负向评价？ → `negative`
2. 标题是否**明确表达**赞许、支持、满意或其他正向评价？ → `positive`
3. 标题是否**同时**表达清楚的正负两面、无法归为单向？ → 记为 `uncertain` 并在
   rationale 说明"mixed"（或按第 8 节确认后的规则处理）
4. 标题是否过短、歧义过大、无足够线索？ → 记为 `uncertain` 并在 rationale 说明"unclear"
5. 以上都不是 → `neutral`（标题主要在陈述事件或转述指称）

**关键区分：转述不等于评价。** 用 `allegedly`、`lawsuit claims`、`Sued Over` 等词
转述他人指称的标题，本身没有表达标题作者的评价立场 → `neutral`。
但若标题把负面结果直接陈述为事实（如"hit with a breach"、"Won't Pay"），
措辞本身带负向色彩 → `negative`。

**不要把事件严重程度当作情感强度。** 一起严重的网络攻击事件，若标题只是客观陈述
"shuts down network"，仍是 `neutral`；标签只看措辞。

## 6. 交付载体

| 文件 | 位置 | 用途 |
| --- | --- | --- |
| 答题表 | 由工作 Agent 生成到证据目录 | 人读 + 填 |
| 提交壳 A / B | 同上 | 填完的答案单，格式与 v16（`units[]`）/ v18（`records[]`）一致 |
| 校验器 | `src/riskshield/evaluation_annotation.py` | 校验槽位、哈希、标签集、独立性、时间戳 |

建议标注者**填 CSV**（不易破坏 JSON 结构），由工作 Agent 转换为标准提交文件并记哈希。

## 7. 独立性要求（硬性）

- 同一单位的两名标注者必须是**不同的人**。
- 两名标注者**不得**看到对方答案；提交前不得互相讨论具体标题。
- 不得看到任何模型预测、AI 标注建议、旧摘要答案。
- 具体到本材料：`agent-sentiment-suggestions-v20.json`、
  `human-review-ai-suggestions-v22.json`、`human-sentiment-submissions-v16/v17/v18.json`
  都**不得**作为标注者的参考——它们属于预测侧或旧答案。
- `verified-original-titles-v19.json` 中的 `v4_text_to_annotate` 与
  `prior_submission_disposition` 也不得展示（含旧答案线索）。
- 已完成的 5 个单位（sent-*）与 v19 的 14 个标题**不重叠**，可并行，不构成冲突。

## 8. 待确认项（阻塞正式计分，不阻塞填写）

1. **允许标签集合**（必须由总 Agent 确认）：
   - 选项 1（建议）：允许 4 个标签，并给出 `uncertain` 的定义 —— 保留弃权，
     弃权样本单列不进分母；
   - 选项 2：只允许 3 类，`mixed`/`unclear` 归入 `neutral` 并写明；
   - 选项 3：允许 4 个标签，把 `mixed`/`unclear` 映射进 `uncertain` 的定义。
2. **争议处理**：两名标注者不一致时，是交由第三名裁决，还是整条弃权（`uncertain`）？
   冻结协议要求"分歧需裁决记录"；建议保留两稿原文后再裁决，不强迫一致。
3. **走势方向标签规则**：与本文件无关，需另行冻结（见交接 v03 第 7 节）。

## 9. 校验通过后的处理

1. 两稿原文分别冻结为独立提交文件，记 SHA-256。
2. 计算标签一致率；不一致的单列，不进入正式分母，除非有裁决记录。
3. 交付 `data-evaluation` 侧走已有准入与计分链路（`evaluation_prediction_import.py` +
   `evaluation_alignment.py`）。
4. **注意**：人工标注齐备只解决"标签侧"。要形成非零正式分母，仍需**配对的正式预测产物**
   （见[预测产物契约提案](prediction-artifact-contract-proposal-2026-10-11.md)）。
   两者缺一不可。
