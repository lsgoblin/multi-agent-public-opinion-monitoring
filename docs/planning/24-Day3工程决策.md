> 更新：2026-10-06。状态：工程决策，非 G3 验收记录。用户已授权 Day 3，未授权 Day 4—5；随后仅授权并完成一次纯合成 Day 3 小规模云端验证，真实来源外发仍未授权。依据：[新版命题](../sources/2026-09-30-新版命题-多智能体仿真舆情监测.md)、[架构设计](../design/02-系统架构设计.md)、[五日计划](03-五日施工计划.md)及[Day 2 受限复核](../records/23-Day2受限G2关口复核.md)。

## 决定

1. **轮次与参与。** 暂将一轮定义为一个同步时间步：冻结轮初状态，按 Agent 的局部观测并发请求独立决策，全部有效响应或显式失败落账后统一传播消息、更新状态和记忆。轮内并发数可配置，不能把批次顺序造成的信息泄漏当作交互。正式“并行”口径仍按 V2-Q04 待确认，不据暂定实现改写指标。目标运行必须记录 500 个不同 Agent 在 30 轮中的逐轮状态、参与和失败；只配置 500 个 ID 不算规模完成。
2. **独立性与来源。** 每个 Agent 拥有独立 persona、局部状态、邻居、消息收件箱和按 `run_id + agent_id` 隔离的持久记忆。新运行默认不继承旧运行记忆。图检索只读本次案例的截止快照及其版本，检索结果记录来源和 `available_at`；未知可见时间、`evaluation_only` 与截止后材料不能进入观测、消息种子或记忆。
3. **动态决策。** 每轮决策输入包含该 Agent 本轮可见的证据引用、邻居上轮实际动作所产生的消息、当前局部状态和检索出的自身记忆。动作在运行时由真实模型产生并校验；预定义动作枚举和状态更新规则可以使用，预写逐轮结果、回放、固定脚本或复制同一输出不能作为 G3 证据。消息传播必须改变后续轮次的可见输入，并在日志中连到触发动作与接收者。
4. **日志与失败。** 保存运行配置和版本、逐轮冻结状态摘要、每次请求与响应状态、Agent 动作、证据/记忆/消息引用、状态变化、传播边、重试、跳过与失败原因。区分配置人数、实际决策人数、逐轮活跃人数及完成轮数。模型调用失败不能悄悄改写为 `observe`；无有效动作时显式记失败和下一轮状态处理。
5. **费用闸门。** 当前单次完整任务费用上限为 ¥5.00，覆盖该任务的构图、Agent 决策、记忆处理及后续报告调用；用户于 2026-10-05 先将 ¥2.38 修正为 ¥2.36，随后提高至 ¥5.00。发请求前按模型、价格版本、最大输入/输出 token 和并发请求数原子预留保守费用，回执后按实际 usage 核销；缺 usage 时保留保守预留并标未知。达到可用余额边界即停止派发，结果为 `partial`，不得记作完整 500 × 30。记录估算费用与供应商账单的区别，套餐或免费额度抵扣不把任务费用记为零。既往试验的单独授权额度不追溯提高。
6. **执行顺序。** 先验证独立状态与记忆恢复、消息因果、时间隔离、失败和预算闸门，再以 1×1、10×3、50×5、100×10、500×30 分级运行。测试替身只验证工程逻辑；G3 须另有真实模型的完整规模实测、实际用量和失败日志。上一级若暴露预算或稳定性问题，先修复或如实停止，不用小规模结果外推 G3 通过。

## 2026-10-05 小规模运行后的工程决定

[受限运行记录](../records/25-Day3动态仿真工程验证.md)显示，获准的纯合成 10 Agent × 3 轮真实模型运行完成 30/30 次有效决策，供应商回执 10,464 tokens，估算费用 ¥0.036972；每轮均为 9 个 `observe` 和 1 个 `seek_clarification`，无消息传播。记忆进入局部上下文且被引用，**引用本身不能证明记忆改变行为**。这项运行的授权已经执行完毕，不据此追加 DeepSeek 请求。

1. **先验证行为因果。** 下一次云端试验前，先离线审查真实运行的动作分布、提示词和消息字段，并冻结一个纯合成的对照方案：保持角色、初始状态和截止前证据一致，只改变一条由运行时 Agent 动作产生、在下一轮送达的模拟消息。记录发送动作、`message_id`、接收者观测、接收者动作和理由；另设无该消息的对照观测。模型引用 `message_id` 但动作与解释不变，只能证明读取，不能证明行为因果。对照或诊断回放不计作 G3 规模证据。下一次收费调用需另获明确的次数、字段和预算授权。
2. **不启动全员逐轮云调用规模试验。** 当时按 10×3 实际平均费用直接外推，15,000 次同类 DeepSeek 请求约 ¥18.486，约为当时 ¥2.36 上限的 7.83 倍；即使按当前 ¥5.00 上限仍超出。这是容量估算，不是最终报价或账单。现行“500 Agent 每轮各一次云端决策”的实现路径无法凭当前证据承诺预算内完成。先做无费用的参数和调用量测算，再评估保持 500 个独立运行时状态与 30 轮同步推进的降本方案；逐轮实际决策人数、模型决策人数和本地状态更新人数必须分别报告。正式“并行”和参与口径未确认前，稀疏方案不得宣称 G3 通过，也不能用测试替身代替真实规模实测。
3. **关口状态。** 真实模型行为因果与预算内完整规模实测均缺失，G3 继续记为未通过。未获 Day 4 授权，不进入报告、预警、通知或部署工作。

用户随后授权一次 ¥2.36 的纯合成 DeepSeek 调用上限测试。[实测记录](../records/27-Day3纯合成调用预算上限实测.md)在假日价加 10% 缓冲的保护规则下发送 4,140 次请求、得到 4,137 次有效决策，剩余保护额度不足下一请求预留。该多片段调用容量结果不改变上述 G3 判据；真实模型 500 × 30 连续完整规模和行为因果仍未通过。

用户随后将**后续单次完整任务**费用硬上限提高至 ¥5.00。该变更不扩大此前 ¥2.36 探针或 10×3 测试的单独授权，不授权百炼或其他新供应商外发，不构成新的调用证据。按 4,140 次 DeepSeek 容量实测的假日价加 10% 缓冲线性外推，15,000 次约 ¥8.48，仍高于新上限；此前提出的千问混合模型 ¥1.95～¥2.24 仅是按旧模型 token 分布和百炼公开单价的纸面估算，尚无千问实测。G3 保持未通过。
