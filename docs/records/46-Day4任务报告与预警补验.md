## 决定

已打通一个真实历史案例到本机动态替身、五模块报告、暂定预警及企微／邮件 dry-run 预览的接口链。运行使用 `offline_dynamic_substitute`，没有模型调用或外部网络请求；这证明的是本机工程闭环，不是真实模型推演、真实舆情走势或通知送达。

G3 **尚未通过**。G4 仅按本记录中的离线证据逐项核验；真实模型、实际通知送达、平台采集覆盖及域内运行仍无证据，G4 **整体未通过**。

## 核查发现与实现

本机运行库已导入 UnitedHealth Group / Change Healthcare Day 2 案例，但没有保留该案例的观察行或 Day 2 图谱。旧任务执行器又只接收纯合成运行，因此真实材料原先无法进入 Day 4 任务队列。

在授权范围内补齐了以下本机路径：

- [任务执行器](../../src/riskshield/tasks.py)新增真实历史案例入口。若已有合格观察，优先走 Day 2 图构建；若没有观察行，只从本机快照中发布时间、可见时间均不晚于 cutoff 且 `historical_integrity=archived` 的来源，构造明确标记为 `offline_archived_record_projection` 的本地图投影。投影保留来源版本、可见时间依据和收录范围；不在线回采，也不伪称为原 Day 2 GraphRAG 图。
- 每个本机任务在 Agent 取得上下文前重新核对案例、图、版本、cutoff、来源角色、数据模式、发布时间、可见时间和来源内容。未知可见时间、未来材料、评测材料、改写 claim 或跨案例图会在推演前被拒绝并留下 `data_integrity_error`。
- [API](../../src/riskshield/api.py)新增 `POST /day4/historical/jobs`；[Web](../../ui/app.py)为真实历史案例提供受限的本机任务入口，并展示数据模式、执行模式、任务输入、报告生成时间及耗时。
- [五模块报告](../../src/riskshield/reporting.py)在根级和五个模块内都绑定同一 `case_id`、`graph_id`、`run_id`，并记录执行模式与图构建模式。来源、决策、消息和记忆以 ID 引用追溯。
- [预警模块](../../src/riskshield/alerts.py)记录本机规则评估时间为 `discovered_at`，并记录评估到预览生成的毫秒数。该时刻不等于历史事件首次公开或实际送达时间。

## 四级规则与载荷

对纯合成 20 决策场景逐级验证；每级均生成企业微信和邮件预览，共 8 份载荷。暂定规则边界为红 ≥40%、橙 ≥20%、黄 ≥5%、其余蓝。

| 合成投诉意向 | 占比 | 等级 | 企业微信评估至预览 | 邮件评估至预览 |
| ---: | ---: | --- | ---: | ---: |
| 8 / 20 | 40% | 红 | 4.108 ms | 10.455 ms |
| 4 / 20 | 20% | 橙 | 6.620 ms | 10.884 ms |
| 1 / 20 | 5% | 黄 | 6.063 ms | 10.444 ms |
| 0 / 20 | 0% | 蓝 | 4.283 ms | 10.418 ms |

企微载荷为 `msgtype=text`，邮件载荷包含 `[OFFLINE PREVIEW]` 主题和正文；八份载荷均带 `OFFLINE PREVIEW ONLY`，`delivery_status=dry_run`，没有收件人、发送时间或网络请求。阈值未经真实事件校准。各场景载荷和计时见[纯合成预警矩阵](../../artifacts/day4-task-acceptance/synthetic-alert-matrix.json)。

## 失败、重复执行与验证

- 将 cutoff 图中的来源时间篡改到未来后，任务持久化为 `failed / data_integrity_error`；Agent 轨迹为空，说明严格校验发生在 Agent 读取上下文之前。
- 对同一 `run_id` 重复调用任务启动，返回原 `job_id`，不生成第二份任务；已完成任务重复启动仍返回原完成记录。
- Streamlit 离线 UI 测试覆盖历史任务启动、失败显示、进度时间和报告／预警 ID 展示。
- `uv run pytest -q`：**147 passed**，1 条既有 Starlette/httpx 弃用警告。
