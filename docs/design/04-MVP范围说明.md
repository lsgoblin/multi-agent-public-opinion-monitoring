# MVP 范围说明（V2）

> 更新日期：2026-10-08。依据：[新版命题](../sources/2026-09-30-新版命题-多智能体仿真舆情监测.md)。五日目标为可演示版本；正式验收要求保持不变，未完成项须明示。

## 1. 必须完成的目标范围

| 范围 | 最小可交付行为 | 必须保留的验收边界 |
| --- | --- | --- |
| 公开多平台采集 | 按来源获取、去重、可溯源、监控延迟，支持事件输入后补采 | ≥5 平台、热点延迟 ≤15 分钟；人工导入不计在线接入 |
| 识别与 GraphRAG | 情感三分类、负面判断、事件归并；抽取并检索带来源的知识关系 | 负面准确率 ≥90%、召回 ≥85%、三分类准确率 ≥88%；绘图不替代检索增强 |
| 人设、记忆与动态仿真 | 独立状态与持久记忆，运行时观测、决策、传播和更新 | ≥500 Agent、≥30 轮；小规模调试不代表规模通过 |
| 走势与报告 | 新运行产生升级/平息方向及完整五模块报告 | 方向一致率 ≥70%；报告 ≤60 分钟；所有结论绑定交互与来源 |
| 预警与通知 | 红橙黄蓝、初警/升级、企业微信与邮件适配及状态 | 红色发现到推送 ≤30 分钟；两渠道如何验收见待确认项 |
| Web 与集成 | 任务配置、进度、知识图谱、看板、报告、自然语言追问；服务接口支持独立及嵌入调用 | 追问基于本次真实证据；可操作页面，不只静态截图 |
| 部署、预算与交付 | Docker 一键启动、域内依赖路径、任务 token 上限和费用统计；四类文档 | 数据不出域须验证模型等外部依赖；当前单任务 ¥30.00 上限已确认，平均费用仍需实测 |
| 历史回测 | 独立真实事件、情感与方向标签、无未来泄漏、逐项测试报告 | “不少于 10—20 个”确切要求待确认；不能把转载数当事件数 |

上表是目标清单，不是对五日完成率的保证。当前已完成 Day 1/G1 和 Day 2/G2 的受限内部关口；Day 4 本机闭环、Docker 功能项及受限 Day 5 评测/核查/文档已落地，G3/G4/G5 尚未通过；实现与正式指标差距见[项目现状](../planning/00-规划总览与待确认事项.md)。

## 2. 可以简化的实现

- 使用模块化单体 API 与独立任务 worker，复用现有 SQLite 和界面原型；以性能证据决定是否升级存储，无需先建微服务集群。
- 图谱先覆盖人物/组织/产品/事件/回应等必要实体和关系；以可溯源的局部子图检索完成 GraphRAG，不追求全网知识图谱。
- 多种角色可共用同一模型；人设、可见信息、状态和记忆仍须独立。批量请求须隔离每个角色的上下文与决策。
- 长期记忆先实现跨轮持久保存、检索和恢复；是否跨事件复用见 V2-Q15，默认隔离评测事件，不能泄漏未来标签。
- Web 采用朴素布局、基础曲线和图谱交互；不以视觉复刻 MiroFish 作为前置条件。保留全部必需用户功能。
- 报告可采用固定五节结构；各节的结论、曲线和节点必须由实际运行生成。模板结构不是预设仿真剧情。
- 部署先覆盖单机内网和一个受控演示使用场景；最低访问限制、凭据保护、审计与数据边界仍保留。
- 通知开发可使用替身测试重试和去重；正式送达证据需确认的测试收件人/群，替身不计时效通过。

## 3. 暂不实现

暂不建设生产级多租户、复杂组织权限、跨地域容灾、全自动危机处置、真实社交平台自动发帖、自动联系投诉人、私有登录数据采集和通用全网爬虫平台。

历史投诉可作为真实事件输入，不因预测目标取消而禁止使用；但没有投诉样本不再阻塞其他合规真实舆情事件的主链开发。

## 4. 演示与验收不能混用

历史材料导入、少量 Agent、云模型和单平台链路可以用于开发阶段演示；若最终只具备这些条件，须逐项标出正式目标差距。动态多智能体不得降级成脚本、固定曲线、单次报告生成或历史轨迹回放。

未明确的平台替换、指标公式、事件数和域内边界列于[00](../planning/00-规划总览与待确认事项.md)，不通过“内部 MVP”自行修改赛题。
