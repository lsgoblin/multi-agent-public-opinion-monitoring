# 事件走势评测协议修订提案（2026-10-14）

> 状态：`data-evaluation` 提案，待总 Agent 协调确认；不追认旧运行，也不改变[新版命题](../sources/2026-09-30-新版命题-多智能体仿真舆情监测.md)的 ≥70% 方向一致率和本任务要求的 20 件可评分独立真实事件。当前没有正式非零分母。

## 发现的问题

旧公司名宽泛命中数没有事件归属，有时连查询覆盖也不能证明；只用严格标题词组又会漏掉相关帖子。一个开发诊断中，State Farm 2023 年加州新保单事件的基线原始检索为 10 帖，固定标题规则留下 7 帖；观察窗原始检索为 3 帖，规则留下 0 帖。但两个窗口的被排除标题里分别出现了直接谈及停止加州新业务以及监管回应的帖子。因此“规则匹配为零”不能写成“事件讨论为零”，这件诊断样本不能给模型记对错。原始规则和产物保留，不能看结果后改词重算。详情见主工作区 `artifacts/branch-work/data-evaluation/evidence/20261014/fresh-attribution-audit-state-farm-v1.json`。

## 建议冻结的顺序

1. **独立选事件。** 先登记具名公开披露来源及日期、具体动作、主体、与开发事件的关系、来源使用范围和版本；同一事件的后续报道不得拆成多件抬高分母。留出事件须在调方法和阈值之前固定。以 20 件最终可评分为目标，先准备更大的候选池，逐件公布排除原因。
2. **固定检索与时间边界。** 每件事在接触观察窗或预测结果前，定下高召回检索式、实体别名、标题/URL 判读说明、cutoff、等长基线和观察窗、时区。当前“披露日后第七天 00:00 UTC、前后各七个完整 UTC 日且跳过 cutoff 日”只是试行方案。保存所有原始命中 ID、标题、URL、发布时间、查询参数、返回版本和覆盖标记。近似命中、分页截断或失败窗口不能记零；[采集约束](data-evaluation-event-collection.md)给出可穷尽检查。
3. **先审基线归属，再预测。** 对原始命中逐条记录 `include` / `exclude` / `cannot_judge` 与原因；不能只保存规则选中的帖子。正式归属需要两个互不见答案、看不到预测的真人独立判断，分歧保留并记录裁决；暂缺真人时 AI 复核仅用于辅助。若明显相关的原始命中被事前规则漏掉，或检索无法覆盖事件讨论，修订规则只能用于**后续全新留出事件**，当前事件退出该方法的留出集。入选故事 ID 和所属评论构成截止前输入包，哈希冻结。
4. **冻结真实预测。** 真正用于方向指标的行必须是完整真实历史输入的动态多智能体运行导出，含明确的事件 ID↔主记录 ID、cutoff、来源版本、方法版本、独立状态/记忆和消息作用证据、完整轮次、模型调用与 token/费用账本；通过 `evaluation_prediction_import` 的 `live_multi_agent_simulation_v1` 准入后才能参与配对。单模型 qwen-flash、常量基线、`partial` 和 AI 标签只进独立辅助账本。预测输入不得含未来观察或标签，预测文档与冻结记录须在读取观察窗前落盘并核哈希。
5. **再审观察归属。** 按同一高召回检索式抓观察窗新故事和截止前已入选故事的观察窗评论，逐项证明覆盖；观察新故事仍需独立盲审归属。不能把检索式未命中的未知讨论或未通过归属的帖子当作零。故事 ID、评论 ID 全局去重；只汇总事前定义的来源家族，不写成公司全渠道投诉量。
6. **形成独立真值。** 真人标注员在看不到预测和彼此答案的条件下，用已核归属的观察证据分别给 `escalation`、`calming`、`stable` 或 `cannot_judge`；两人一致或有具名裁决才有正式真值。当前备选机械敏感性规则 `B≥20`、同口径 `O/B` 超出 ±10% 才给升/降，仍未批准，也不代替人工判断。`stable` 和 `cannot_judge` 单列覆盖及排除，不能强塞进二分类。规则选择必须在全新留出事件的观察结果和预测揭盲之前完成。
7. **逐单位评分。** 只有事件身份、来源许可、截止前可见性、完整预测、可比观察、独立真人标签同时成立的单位进正式分母。报告列每件证据版本/哈希、预测与真值、排除原因、方向正确数/分母、情感混淆矩阵、负面 precision/accuracy/recall、覆盖和真实调用账本。20 件可评分、方向 ≥70% 以及其他目标均须由实测证明；候选数、AI 一致率、工程测试通过数不算验收。

## 归属不确定时的方向区间规则（新增提案）

开发样本证明，标题或 URL 不足以判断某些报道是否专谈同一事件。不能把 `cannot_judge` 强制纳入或排除，也不能因为旧标题规则漏召回就把观察量记为零。对**事前冻结且两个窗口完全同口径**的一个来源家族，建议按原始帖子 ID 去重，评论继承所属帖子的归属：`include` 帖及评论计入下界，`cannot_judge` 帖及评论只计入上界，`exclude` 不计入。由此得到基线 `[B_L,B_U]` 与观察 `[O_L,O_U]`。如果故事或评论缺窗、查询不穷尽、查询式漏掉已发现的相关帖，区间不封闭，该事件直接标为来源覆盖失败。

方向仅在**所有可能归属取值都给相同结论**时给出。设事前批准的最低基线量为 `T`、中性带为 `δ`，且 `B_L≥T>0`：

| 结论 | 充分条件 | 否则 |
| --- | --- | --- |
| 平息 | `O_U < (1−δ) × B_L` | `cannot_judge` |
| 升级 | `O_L > (1+δ) × B_U` | `cannot_judge` |
| 中性诊断 | `O_L ≥ (1−δ) × B_U` 且 `O_U ≤ (1+δ) × B_L` | 单列，不挤进升级/平息二分类分母 |

`T=20`、`δ=0.10` 仍只是敏感性草案，不能依据已看过的预测或观察结果调到有利值。每件事件保存四个端点、各端点所含 ID、查询和归属版本、排除原因以及规则版本；先冻结规则，再用于完全新的留出事件。两名 AI 可按用户当前授权完成独立辅助填写，输出须注明 AI 来源；它不伪装成真人真值。正式验收准入仍须满足项目总体验收契约和真实多智能体预测证据。

State Farm 2023 **开发诊断**中，两份独立 AI 对 10 个基线原始帖一致纳入；补查旧规则漏掉的 3 帖后，基线为 10 帖加 239 评论，即 `B=249`。观察窗 3 个原始帖中 1 帖一致纳入、2 帖一致判为无法判断；全部原始帖及其评论都算入，上界也只有 `O_U=4`，下界为 `O_L=1`。在草案 `δ=0.10` 下，`4 < 0.9×249`，方向对这两条模糊归属并不敏感；但这是**已参与规则制定的事后查询内敏感性**，既不证明检索式对全事件的召回，也不构成正式真值或模型成绩。冻结的 qwen-flash 单模型辅助预测为 `escalation`，仅能记录为开发诊断中的相反信号。逐 ID、请求覆盖与原件哈希见主工作区 `artifacts/branch-work/data-evaluation/evidence/20261014/annotation/state-farm-count-sensitivity-v1.json`。

## 若采用 GKG 新闻元数据，先冻结观测单位（新增提案）

GKG 的一条记录是一个档案元数据行，不等于独立报道，更不等于一件舆情事件。State Farm 开发样本的一天内，两名 AI 纳入的 34 条记录虽然有 34 个不同完整 URL，但只有 23 个“精确标题 + 去主机名的 URL 路径”组合、12 个精确标题组；其中同一标题与路径跨 12 个站点出现。若把原本针对完整基线窗的未批准 `B≥20` 草案误套到本日数据，按 34 条原始记录或 12 个标题组会得到相反判断，说明计数单位尚未确定，并非对本日作正式准入；逐条核验见主工作区 `artifacts/branch-work/data-evaluation/evidence/20261014/gdelt-gkg2-dev-day-dedup-audit-v1.json`。开发样本不用于选出有利的阈值或正式来源口径。

建议每个拟接入的新闻来源家族事前声明：原始 GKG 记录 ID、全文 URL 与可核历史版本；明确哪些 URL 是聚合或转载、哪些可算独立编辑报道，并保存同稿聚类 ID 与判定证据。完全相同的 URL 可作为确定重复候选；相同标题/路径只标记待核转载，不能无证据自动合并，单靠标题相同也不能抹掉可能独立的报道。对缺标题、来源时间不明和归属无法判断的行单列覆盖与排除原因；档案批次时间不自动等于报道首次可见时间。随后在**未参与制定这些规则的新事件**上，冻结实际可计量的来源单位、基线与观察窗口、聚类裁决和最低量 `T`，再读取观察和预测揭盲。新闻报道量只能对应媒体报道走势，不与 HN 评论或投诉样本合成未定义的“舆情总量”；标题/URL 也不足以给用户情感真值。

## 需要协调的接口

`simulation-scale` 的现有方向导出尚不能直接形成 `prediction_import.v1` 所需的完整历史运行包。请总 Agent 协调增加真实 `backend_mode`、运行配置摘要、可解析 ledger 引用及 `event_id`↔`record_id` 对应；`data-evaluation` 只在本分支实现导入和评分，不改共享 API、schema、网关或仿真分支文件。正式规则与人工盲标排期须由总 Agent 统一确认。

评测侧现在要求 `production_evidence_ref` 另含 `run_ledger_ref`、该对象的 canonical JSON SHA-256 和运行配置 SHA-256。`run_ledger_ref` 应解析到 `riskshield.simulation_scale.run_ledger.v1`，其中 `summary` 是同一 `run_id` 的 `Day3Simulation.summary()` 导出，`trajectory` 是 `Day3Simulation.trajectory()` 的完整动作行；评测器逐轮核对真实模型模式、事件/cutoff/来源版本、Agent 数、完整轮次、有效决策、模型调用、Token 和费用。它不能由评测器根据旧方向预测自行拼造。现有 `direction_prediction.py` 只导出旧 `evaluation-inputs.v1`、`multi_agent_simulation` 及简要摘要，缺上述原始账本和 `prediction_import.v1` 冻结文档；即使把模式字符串改成白名单值也仍应被拒绝。原始账本可能包含请求审计信息，只留在授权的本机证据目录，不纳入源码提交。

评测器另有显式的 `live_simulation_event_frame` 候选入口：配置给出候选事件帧、**原生产者写出的** `prediction_import.v1` 文档；帧逐件声明 `event_id`、主 `target_record_id`、`input_package`、`text_source`、cutoff、来源版本和 split。导入器从真实历史输入包核对该记录及文本哈希，再把原预测文档直接送严格准入，不在评分时生成生产账本或冻结证明。帧的事前登记时间和不可更改性尚未由此入口证实。该入口目前只完成**预测侧准入和排除表**；观察窗来源覆盖、归属和独立真人方向标签尚无经批准的正式验证记录，因此其正式计分门保持关闭。不能把工程夹具通过或预测行准入数写作正式事件分母。

## 本提案的适用边界

本次 State Farm 诊断和已用于开发的旧 10 件不能再为此修订协议充当未参与规则制定的留出证据。Hacker News 当前历史索引可提供条目创建时间，但不是历史时点的完整索引快照；正式结论还须核其来源使用范围、历史可见性和跨来源代表性。[新版命题](../sources/2026-09-30-新版命题-多智能体仿真舆情监测.md)的五平台覆盖另行验收，不能由单一 HN 事件序列代替。
