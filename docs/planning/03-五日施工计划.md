## 1. 资源与组织前提

需要公开舆情与投诉采集、Python 数据建模、Agent 仿真、界面及业务核验能力。按 2026-09-30 用户转述的主办方最新说明，内部数据敏感、暂不可提供，当前不等待数仓开通。先做公开投诉小样本与历史列表覆盖核查，再按数据可得性选案例，见 [自采方案](09-公开投诉自采方案与口径变更.md)。这是工作能力清单，不是已确认团队编制；Q11/Q03/Q10/Q13 仍需落实，本轮不扩展到 Day 2。

定义以下责任职能，可由同一人兼任；多岗位同时推进只有在人力已确认时才成立：

| 职能 | 主要责任 |
| --- | --- |
| P 需求/业务与统筹 | 口径、范围、数据协调、风险、验收及演示 |
| D 数据与后端 | 渠道、质量、存储、数据契约、任务调度 |
| A 算法与仿真 | NLP、Agent、预测、时间切分与评测 |
| V 交互与验证 | 看板、操作闭环、证据展示、集成检验 |

下文按依赖组织工作包，不依赖固定人数。若只有一名实施者，优先单机、单业务域、最少案例和最简看板。若采集或清洗仍需大量协调，在 D1 报告工期和指标风险，不提前承诺五日必成，也不删除仿真与投诉预测。骨架/契约可先开发；真实模型运行、数据训练和验收分别等待其实际资源到位，不要求全部待确认项关闭才开始工程。

## 2. 关键路径

用户确认 → 首个历史案例与输入契约 → 采集/导入和投诉快照 → NLP 分类与事件快照 → 动态仿真 → 投诉预测与多维影响 → 预警与建议 → 历史留出评测。权限、实际数据与模型到位是相应联调关口，五渠道持续在线不再作为主链路开发前置条件。

两条从 D1 开始的支线不可延后：

- 渠道支线：指定五渠道清单 → 历史内容可访问验证 → 一次性采集/带来源导入 → 批次及覆盖证据 → KR1 认定；是否补做持续在线按 Q02 决定。
- 评测支线：标签口径 → 样本质量 → 时间切分 → 基线 → 校准/验证 → 冻结 → 留出测试。主模型未完成时也能先做标签、基线与样本划分。

## 8. 演示路线与证据

建议准备一条完整事件、一个平稳对照和一个异常场景，不以大量案例替代深度核验。

1. 显示五渠道历史采集/导入覆盖、来源和数据模式；在线能力单列。
2. 选择历史案例与 cutoff，查看分类和截止前证据，现场启动动态新推演。
3. 展示一个 Agent 的观测、动作及对其他 Agent 的后续影响，播放真实轨迹。
4. 展示从该历史时点起的 7 日投诉预测、基线和多维影响说明，再揭示后续真实标签。
5. 查看风险等级和触发条件，生成建议并人工确认、记录处置。
6. 打开评测视图，展示五项 KR 的实测值或不可验证原因；必要时展示输入扰动与干预对比。

不强制承诺固定演示分钟数；按 Q13/Q16 确定。可先显示完成记录再启动新运行，但两者必须区分，不能假装新请求立即产生了旧结果。
