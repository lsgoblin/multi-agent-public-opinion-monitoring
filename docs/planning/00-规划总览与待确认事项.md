## 1. 赛题理解与项目现状

当前资料包括[原始赛题](../sources/OPEN-CB-02-多智能体仿真舆情监测与投诉预警.md)、六份规划文档、会议纪要和原始转写，以及 Day 1 工程与审计记录。Git 已初始化并提交过规划资料；Day 1 工程及数据方案已在 `codex/day1-foundation` 提交为 `0d5250c`，包含本地 API、SQLite、资料工作台、导入与契约测试。后续工作区状态以 Git 实查为准。已自行整理 3 条公开新闻摘要，但没有可用于训练的真实日投诉序列或可用模型。会议中的资源承诺不等于已经交付。

项目要解决的是舆情监测与后续业务影响分析割裂的问题。产品需要发现事件、分级分类、推演传播与情绪，并融合历史投诉预测未来 7 日投诉走势。会议同时强调：投诉量不大也可能带来举报、监管关注、声誉和群体维权风险，不能把所有影响都折算为投诉量。基础版展示多维影响及证据，监管态度与具体行动轨迹预测作为增强项。

必须形成以下闭环：多源采集 → NLP 语义分析 → 多智能体动态推演 → 融合历史投诉的预测 → 四级预警 → 前置干预建议。单独做舆情看板、关键词报警或固定剧情动画均不能替代这个闭环。

赛题明确要求：

| 成果 | 原始验收要求 |
| --- | --- |
| KR1 | ≥5 个渠道实时采集 |
| KR2 | 仿真推演与实际走势偏差 ≤20% |
| KR3 | 未来 7 日投诉走势预测准确率 ≥80% |
| KR4 | 红/橙/黄/蓝四级预警，触发及时率 ≥90% |
| KR5 | 干预建议可执行性评分 ≥4/5 |

评审权重为 OKR 贡献度 50%、AI 原生度 20%、可落地性 15%、创新性 10%、演示质量 5%。资源优先投入推演、预测及其验证，再投入流程与演示。动态多智能体仿真是不可削减项；训练、测试和动画展示必须使用真实运行结果。

## 5. 决策与证据原则

- 文档区分“书面要求”“会议澄清”“资源承诺但未交付”“待确认事项”“建议设计”和“实测结果”。会议纪要根据转写整理且未听音校对，名称与事实疑点不转写为既定业务事实。
- 分别记录数据模式（真实在线/真实历史/合成）和执行模式（本次新推演/已有轨迹重放）。真实历史输入可以产生本次动态新推演；仅重放已有结果不能证明现场新运行。合成数据不证明业务准确性。
- 五日内无法等待新事件产生完整未来 7 日标签，应使用已经发生、标签成熟且未用于调参的历史区间回测。上线后 7 日真实效果另行跟踪，不写入五日内已达成结果。
- 五渠道、真实动态仿真、投诉预测均有明确缺项状态。降低规模、频率或模型复杂度不能改写原始 KR。
- Git 初始化及规划提交已由用户另行授权完成。用户本轮已授权 Day 1 工程、必要依赖与本地运行验证；完成后停止，不自动提交本轮修改，不进入 Day 2，不将此次授权扩展为完整五日实施或部署授权。
