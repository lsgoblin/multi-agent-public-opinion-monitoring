# 独立标注规程 v1（准备稿）

本规程只用于已授权本机离线数据准备。正式“负面准确率”公式、走势窗口和历史事件最低数仍待 V2-Q03/Q05/Q06 确认。当前没有形成正式留出集或走势真值。

## 切分与隔离

1. 以 `event_id` 为最小切分单元。SEC、Optum、转载、投诉回复及同事件的不同 `case_id` 同属一个事件，不得跨开发集和留出集。
2. 已被 Day 1—Day 5 探测、初标和模型试算使用的 `unh_change_cyberattack_20240222` 固定为开发集。黑猫投诉与众安营销候选因 cutoff 不合格暂不分配。留出集目前为 0 件；新增合格事件须在运行、调参或查看预测前由主 Agent 冻结分配。
3. 预测执行只能读取 `inputs/qualified-inputs-v1.json` 中的截止前快照。`labels/`、后续记录、原事件包中的 `evaluation_only` 记录均不得进入 Store、图谱、检索、Agent 记忆或提示词。审计引用可由评分者在预测封存后查看；预测端不可对包含后续材料的原包做整文件读取。
4. 为每一轮标注保存输入快照 SHA-256、事件 ID、来源记录 ID、指定主体、标注者代号、标注提交时间及实际阅读完成时间（未知填 `null`），并保存其是否已看到目标预测、同事件其他标签/预测和未来材料。缺乏盲态证据写“未知”，不得倒填 `false`。

## 情感：单条来源内容

标注问题：**在冻结的截止前文字中，作者/发布者对指定主体表达什么态度？** 不是判断事件本身是否危险、投诉是否属实或后续走势。标注者只看指定记录的标题、截止前摘要、主体名称与允许核对的当时原件版本。不得打开同包后续更新。

| 标签 | 判断标准 |
| --- | --- |
| `positive` | 明确赞许、支持或肯定指定主体。 |
| `neutral` | 主要客观通报、描述事实或平衡陈述，没有明显赞许或批评；负面事件中的客观披露也可为中性语气。 |
| `negative` | 明确批评、指责或否定指定主体的行为、服务或回应；投诉中的指控只记为发帖者表达，不写成已证事实。 |
| `uncertain` | 主体不清、混合立场无法按单条归类、版本不清或材料不足；不强行三分类。 |

由两名不同真人分别作答，互不见对方答案和目标模型预测。各自提交原始标签、理由、材料版本及时间；分歧保留原答，交第三名未见目标预测的裁决者按同一输入版本裁决并写明依据。裁决失败保留 `uncertain`。Agent 建议或模型标签只能列为 `suggestion_pending_human_review`，不能作为独立人工真值。现有 SEC 的 Leo/Li 同为 `neutral`，但 Leo 的事先暴露情况未知；这是一条有限开发样本，严格双盲真值仍未证实。Optum 的 nike 初标见过同事件其他结果，不计独立真值。

## 走势：一件独立事件

**暂定观察窗**为截止后 `(cutoff, cutoff + 7 × 24 小时]`，以 cutoff 自带时区计算；同一事件只能有一个预先冻结的窗口和一个方向预测。该窗口仅供本数据准备，待 V2-Q05 确认后再冻结正式评测口径。窗口外资料只能作为补充背景，不能给窗口内方向补票。当前 UNH 窗口为 `2024-02-22T16:48:39-05:00` 至 `2024-02-29T16:48:39-05:00`；现有 3 月 8 日 SEC 更新在窗外。

对比 cutoff 附近的可核基线与窗内公开舆情信号。至少记录两个相互独立、带时间和版本的后续观察点，说明传播范围、讨论强度、负面情绪或关键放大节点如何变化，并检查明显相反证据。转载同一报道只算一次信息事件；不同 URL 不自动代表独立观察。标注者须区分公司业务状态和公众舆情走势。

| 结果 | 证据要求 |
| --- | --- |
| `escalation` | 窗内有可复查的、相对基线持续或显著增强的公众传播/负面讨论证据，至少两处独立时间点或来源支撑，并说明未被反证推翻。 |
| `calming` | 窗内有可复查的、相对基线持续减弱的公众传播/负面讨论证据，至少两处独立时间点或来源支撑；单次公司回复、部分服务恢复或一条投诉完成不够。 |
| `stable` | 可见证据显示大体持平；在正式二元方向口径确认前不并入升级/平息分母。 |
| `unknown` | 缺基线、缺窗内独立观察、时间/版本不明、证据冲突无法裁决或走势并非公众舆情；不得为凑数量改判。 |

两名未见预测的真人独立判断，并分别记录 `annotator_id`、`review_completed_at`、`submitted_at`、`prediction_seen`、证据文件/URL/版本/时间、同向与反向证据、理由。分歧交第三人审查；第三人仍不能看到预测。保存原判与裁决链。未取得足量证据时写 `observed_direction: null` 和原因；当前三个候选事件均为此状态。

## 空白记录格式

```json
{
  "event_id": "",
  "record_id_for_sentiment": null,
  "input_snapshot_sha256": "",
  "label_kind": "sentiment_or_direction",
  "annotator_id": "",
  "review_completed_at": null,
  "submitted_at": null,
  "prediction_seen_before_answer": "unknown",
  "same_event_other_results_seen": "unknown",
  "materials_seen": [],
  "label": null,
  "supporting_evidence": [],
  "contrary_evidence": [],
  "reason": "",
  "disagreement_with": [],
  "adjudication_id": null
}
```

空白格式供人工分别填写，不能预填 `label`、未来结果或预测值。记录原件应只进 `labels/` 或独立评分存储，不能回填 `inputs/`。
