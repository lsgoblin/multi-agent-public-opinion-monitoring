# Day 3 跨轮请求上界与百炼验证准备

> 2026-10-06。状态：已完成跨轮输入上界、费用预留、可重复运行入口和消息因果对照方案的离线修复。**本轮没有向百炼或其他云端模型发起请求，G3 仍未通过。**

## 问题复现与修复

[百炼 1×1 记录](29-Day3百炼1x1真实连通验证.md)的实际首轮决策已保存在本地 SQLite。用该决策生成该 Agent 的一条自身记忆，再重建第 2 轮观测，适配器的保守上界为：

- 系统提示 UTF-8 字节：388。
- 第 2 轮用户字段 UTF-8 字节：728。
- 聊天协议固定余量：128。
- 总保守上界：`388 + 728 + 128 = 1,244`，大于原配置 1,200。

[百炼适配器](../../src/riskshield/day3_bailian.py)现将请求构建与 HTTP 发送分开：`prepare_request()` 可在不启用云调用时构建完整脱敏请求，并用“系统提示字节 + 用户字段字节 + 128”作为无本地 tokenizer 时的保守 token 上界。当前有界字段最多保留 2 条虚构证据、3 条实际收到的消息和 3 条该 Agent 自身记忆；它们没有被删除来绕过边界。

输入保守上界提高到 **8,192**：

- 实际 1×1 决策重建的第 2 轮为 1,244。
- 2 Agent × 30 轮离线引擎运行中，第 2 轮和第 30 轮的收件消息与自身记忆均进入请求。
- 用中文长文本、100 字符 ID、2 条证据、3 条消息和 3 条记忆构造的第 30 轮边界请求约为 7,600，低于 8,192。

费用预留与输入上界同步调整。按 2026-10-06 已核对的 `qwen-turbo` 北京标价，单次保守预留为：

```text
8,192 × ¥0.3/百万 + 160 × ¥0.6/百万 = ¥0.0025536
```

这高于 1×1 运行时的 ¥0.000456 旧预留，但不改写那次已发生调用的历史账本。以新上界对 500 Agent 整轮预留时，仅 200 个 `qwen-turbo` 请求就需 ¥0.51072；`qwen-flash` 部分尚须按首次调用前核对的标价另行加入。因此新上界解决了跨轮拒绝，也更清楚地显示编写本记录时保守预留与 500×30、¥5.00 闸门之间的容量差距。后续上限调整见[31 号记录](31-Day3预算上限调整与DeepSeek历史额度核查.md)。

## 可重复运行入口

[百炼运行入口](../../src/riskshield/day3_bailian_run.py)具有以下硬约束：

1. 不在 import 时运行；必须显式传入 `--enable-live`。
2. 从指定 `.env` 读取 `DASHSCOPE_API_KEY` 或 `BAILIAN_API_KEY` 以及实际所需模型的价格版本和三类 token 单价；不从通用网关变量临时映射。
3. `max_calls` 必须等于 `agent_count × rounds`；本记录编写时预算必须在 `(0, ¥5.00]`，现已调整为 `(0, ¥30.00]`；输出文件已存在时在调用前拒绝覆盖。
4. `role_offset=2` 可为获准的 1 Agent 连通试验生成 `media` 角色，从而单独路由到 `qwen-flash`；默认 `role_offset=0` 保持现有角色序列。该值写入运行配置，跨轮不变。
5. 输出保存完成轮数、预期/有效/失败决策数、模型版本、分模型 usage 与费用、动作引用、消息 ID/发送者/接收者/动作及消息内容哈希。密钥、完整提示和消息正文不写入运行结果。
6. `completed_without_failures` 只在目标轮次全部完成、动作数等于预期且失败为 0 时为真。`run_status=complete` 但含失败决策时不会被记为无失败完成。

[配置样例](../../.env.example)已写入 2026-10-06 核对的 `qwen-turbo` 价格版本与单价，密钥仍留空。`qwen-flash` 价格仍留空，必须在其首次请求前核对并填入，不沿用纸面估算。

## 真实模型消息因果对照方案

后续获准后按以下流程执行，不使用预写消息或回放：

1. 使用 2 个纯合成 Agent 冻结首轮状态、证据和人设，让发送者由真实模型产生运行时动作。
2. 只当发送者的实际动作为 `share`/`comment`/`express_complaint_intent` 并产生持久化 `message_id` 时继续；若为 `observe` 或 `seek_clarification`，该次记为“未产生处理消息，因果结果不可判定”，不伪造消息。
3. 从受众 Agent 的第 2 轮观测构建两个冻结输入：处理组包含上轮实际消息；对照组只移除 `received_simulated_messages` 中的该消息和对应允许引用 ID。两组的角色、证据、自身记忆、局部状态、轮次和生成参数相同。
4. 两个受众请求均使用非思考、`temperature=0` 和相同模型路由；记录发送动作、`message_id`、两个输入的脱敏哈希、接收者动作、引用 ID 和理由。
5. **严格通过**要求处理组与对照组的动作不同，且处理组引用真实 `message_id`，理由明确说明该消息影响了决策。只引用消息但动作不变不算因果通过。
6. 结果分别报告实际发送请求数、完成轮数、有效决策、失败和不可判定数；测试替身或对照构造本身不计作 G3 证据。
