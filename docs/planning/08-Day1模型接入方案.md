## 3. 当前工程接入方式

工程读取进程环境变量，不自动读取 `.env`。原 `.env.example` 仅作字段说明，当前工作区已删除该文件，此处不要求恢复。需要配置：

- `RISKSHIELD_MODEL_BASE_URL`：提供方确认的兼容 API 基址，不含 `/chat/completions` 后缀。
- `RISKSHIELD_MODEL_NAME`：实际可用模型 ID。
- `RISKSHIELD_MODEL_API_KEY`：本地设置的真实凭据。
- `RISKSHIELD_ENABLE_MODEL_PROBE=1`：显式启用真实探测。

配置后，在同一终端执行：

```powershell
uv run python -m riskshield.cli model-status
uv run python -m riskshield.cli probe-model
```

使用 API 探测时，服务进程也必须继承上述环境；配置变化后重新启动。没有配置时 CLI 返回 `blocked` 与退出码 2；API 返回 HTTP 503。工作台不收集密钥、不提供自动模型调用按钮。

## 4. 探测内容和通过标准

只发送一段虚构产品的合成描述及动作 schema，最多生成 512 tokens，请求超时 30 秒，不自动重试，不读取公开案例或内部数据。

通过条件：HTTP 200、正常结束、返回可解析且符合契约的 JSON、agent_id 正确、只引用给定证据。记录实际模型名称、返回动作与耗时。配置存在只代表 `configured_unverified`，不能等同测试通过。

当前契约包含 agent_id、action、evidence_ids、reason。这里只检查一个决策的输入输出，**不是多智能体循环，更不是仿真准确性验证**。后续动态仿真仍需独立状态、局部观测、多 Agent 互动和数值状态转移。
